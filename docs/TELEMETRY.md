# Документация Телеметрии и Детектора Спотыканий (SofDom Telemetry)

Модуль телеметрии («Шотчик») предназначен для сбора аналитики поведения пользователей, измерения воронки конверсий и автоматического выявления технических сбоев (битые фото, пустые поисковые выдачи, ошибки карт).

Реализация выполнена по стандарту аналитики **Komfort Go** (`analytics.ts`).

---

## 1. Архитектурные принципы

1. **Fire-and-forget (неблокирующий сбор):**
   - Телеметрия не блокирует основной поток браузера, не задерживает отрисовку интерфейса и не прерывает действия пользователя.
2. **Кольцевой буфер в `localStorage`:**
   - Все события пишутся в буфер `sofdom_telemetry_events_v1` (лимит 50 последних записей). При заполнении буфера старые события циклично вытесняются новыми.
3. **Анонимность и приватность:**
   - Не собираются персональные данные, пароли или токены. Фиксируются только обезличенный ID сессии, таймстемпы и идентификаторы просмотренных квартир.

---

## 2. Модель сессии и жизненный цикл

При открытии витрины модуль `telemetry.ts` инициализирует уникальный идентификатор сессии:
```typescript
const sessionId = 'ses_' + Math.random().toString(36).slice(2, 10);
```

- **Старт сессии (`session_start`):** фиксирует разрешение экрана, реферер и User-Agent.
- **Пульс сессии (`session_heartbeat`):** периодически замеряет активное время пользователя на вкладке (когда документ находится в фокусе `document.visibilityState === 'visible'`).
- **Завершение сессии (`session_end`):** отправляется при событии `pagehide` или `beforeunload` с суммарной длительностью визита.

---

## 3. Воронка конверсий (5 этапов пути пользователя)

```
[1. Витрина] ────────> [2. Скролл 50%] ────────> [3. Карточка] ────────> [4. Галерея] ────────> [5. Телефон]
  1 240 чел.              890 чел.                 540 чел.                390 чел.               285 чел.
   (100%)                 (71.8%)                  (43.5%)                 (31.5%)                (23.0%)
```

1. **Заход на витрину (`session_start`):** пользователь открыл каталог предложений.
2. **Изучение каталога (`scroll_depth`):** пассивный `scroll`-слушатель с debounce отслеживает прохождение порогов: **25%**, **50%**, **75%** и **100%** высоты страницы.
3. **Клик по карточке (`listing_view`):** открытие детального экрана квартиры. Фиксируются `offerId`, заголовок и цена.
4. **Просмотр фотогалереи и Lightbox (`gallery_swipe`, `lightbox_open`):** листание фото в карточке или запуск полноэкранного модального окна с зумом 2x.
5. **Раскрытие телефона (`phone_reveal_click`):** клик по кнопке «Позвонить хозяину» в Sticky Action Dock или показ номера. Главное целевое действие сервиса.
6. **Избранное (`favorite_toggle`):** отслеживание сохранения квартир в избранное для оценки привлекательности объектов.
7. **Снятие с публикации (`unpublish_toggle`):** фиксация перевода квартиры в статус «Сдано» или возврата в поиск.

## 4. Детектор спотыканий (Friction Log)

Детектор предназначен для ответа на вопрос: *«Где и почему пользователи спотыкаются или уходят без контакта?»*.

### 4.1. Битые фотографии на CDN (`broken_photo_cdn`)
- **Как перехватывается:** В компонентах `ListingCard.tsx` и `DetailPage.tsx` на теге `<img>` установлен обработчик `onError`:
  ```typescript
  onError={(e) => {
    trackFriction('broken_photo_cdn', { url: photoUrl, offerId: offer.id });
    // Автоматическая подмена на заглушку или кэшированный дубль
    e.currentTarget.src = FALLBACK_PHOTO_URL;
  }}
  ```
- **Эффект:** пользователь не видит «сломанную» иконку картинки, а администратор в панели видит точный URL и ID объявления, где CDN дал сбой.

### 4.2. Нулевая выдача по фильтрам (`zero_search_results`)
- **Как перехватывается:** В `App.tsx`, если после применения фильтров (цена, комнатность, район) список результатов пуст (`filteredOffers.length === 0`), отправляется событие с введенными параметрами поиска.
- **Эффект:** позволяет выявлять неудовлетворенный спрос (например, «1-комнатные в Советском районе до 15 000 ₽») и расширять базу в этом сегменте.

### 4.3. Задержка тайлов Яндекс.Карт (`map_tile_latency`)
- Замер времени от монтирования компонента карты до триггера `ymaps.ready()`. Если задержка превышает 3.5 секунды, система переключается в облегченный режим рендеринга маркеров.

### 4.4. Отказ в доступе к геопозиции (`geolocation_denied`)
- Фиксирует клик «Определить мой район», завершившийся отказом пользователя в браузере. Приложение мгновенно открывает всплывающий список ручного выбора района.

---

## 5. Отображение в Панели Администратора

Вся информация из буфера телеметрии собирается и агрегируется на экране **«Аналитика и датчики»** (`admin/src/pages/Analytics.tsx`):
- Наглядные прогресс-бары этапов воронки с подсчетом отвалов.
- Журнал живых сессий с длительностью и глубиной изучения.
- Интерактивный список спотыканий со статусом решения проблемы.
