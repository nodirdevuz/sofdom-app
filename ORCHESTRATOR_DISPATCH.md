## ⚡ Жёсткие правила для обоих агентов (MacBook Air M5)

1. **Батарея:** Все запущенные процессы (`vite`, `python`, `node`, `watch`, тесты) ОСТАНАВЛИВАТЬ сразу после проверки. В фоне ничего не оставлять (`lsof -i`, `ps aux | grep vite`).
2. **Синхронизация Git:**
   - Перед любой задачей:
     ```bash
     git pull origin main # или: git pull sofdom main
     ```
   - При изменении фронтенда:
     ```bash
     cd frontend && npm run build
     cp dist/index.html ../index.html
     ```
   - Пуш только после успешного билда и без флага `--force`.
3. **Единый стандарт данных:**
   - Все ID объявлений: только фирменный формат SofDom (`SD-1001` .. `SD-1170`). Никаких сторонних префиксов в UI.
   - Статусы лотов: `'active'` (в поиске), `'rented'` (сдано/снято), `'archived'` (архив).
   - Локальное хранилище статусов: `sofdom_rented_offers_v1`.

## 🤖 Автоматический обмен задачами и отчётами через Notion Tasks

Для исключения ручного переноса сообщений человеком настроен автоматический асинхронный цикл через базу **Notion Tasks** (ID: `3d3ee85c-f124-80e3-b7ea-c3a0dc3a9f60`):

1. **Как Оркестратор ставит задачу:**
   * В Notion в базе `Tasks` создать задачу со статусом **`Up next`** (или через CLI: `python3 backend/notion_bridge.py create --title "..." --body "..."`).
   * В теле страницы указать полный текст ТЗ, требования и проверяемые файлы.
2. **Как Агент-партнёр забирает задачу:**
   * Каждые 4 минуты фоновый планировщик Antigravity опрашивает `Tasks` со статусом `Up next`.
   * При обнаружении задачи агент переводит статус в **`In progress`**, считывает ТЗ и начинает реализацию в коде.
3. **Как Агент-партнёр сдаёт результат:**
   * После выполнения кода и всех тестов агент прикрепляет полный отчёт (дифф, результат тестов, коммит) прямо в конец страницы задачи в Notion.
   * Статус задачи переводится в **`Done`**.
4. **Как Оркестратор принимает задачу:**
   * Оркестратор открывает выполненную задачу (`Done`), читает отчёт исполнителя и проводит независимый аудит. При замечаниях переводит статус обратно в `Up next` с комментариями.

## 🔔 Локальные уведомления о новых отчётах

На macOS можно включить read-only LaunchAgent, который каждые 8 минут проверяет `Done` в Notion Tasks и показывает системное уведомление при появлении нового или изменённого блока отчёта. Он не меняет страницы, статусы, код или Git.

```bash
python3 backend/notion_report_watcher.py poll
python3 backend/notion_report_watcher.py install
python3 backend/notion_report_watcher.py status
python3 backend/notion_report_watcher.py uninstall
```

При первом `poll` сохраняется тихий baseline существующих отчётов без уведомлений. Учётные данные читаются через существующий локальный Notion bridge; OAuth Notion MCP автоматически не переиспользуется. Состояние хранится отдельно от репозитория в `~/Library/Application Support/SofDom/NotionReportWatcher/`, логи — в `~/Library/Logs/SofDom/`. После переноса проекта на другой Mac LaunchAgent нужно установить там заново; на обоих Mac должны быть настроены локальный Notion bridge и доступ к базе Tasks. LaunchAgent работает, пока пользователь вошёл в macOS и компьютер не спит.
